# 方案缩略图与保存时自动截图

## Context

当前“打开方案”界面只有名称和时间，无法快速辨认方案；方案 JSON 与列表接口也不包含预览图。本次在不改变现有方案加载、自动保存和 JSON 格式的前提下，为手动保存生成当前方案的 2D PNG 缩略图，并显示在“打开方案”卡片中。

## 实施方案

### 1. 复用 2D PNG 生成逻辑

修改 `index.html` 中现有 `exportPNG`（约 L5083-L5102）：

- 抽出可复用的 `svgToPngBlob(width)`，沿用当前克隆 `svg#plan`、按 `BOUNDS` 设置完整户型视图、移除选择框、补背景和网格、SVG 序列化后通过 `Image + canvas` 转 PNG 的流程。
- Promise 返回 PNG `Blob`，补充图片加载失败及 `canvas.toBlob` 返回空值的错误处理；原“导出图片”继续下载 3200 宽 PNG，保持原有使用方式。
- 手动保存时以 480 宽（约 480×434）生成缩略图。直接读取持续存在且与状态同步的 2D SVG；当前处于 3D 时不调用 `setView`，避免界面切换和异步时序问题。

### 2. 保存并上传同名缩略图

修改 `index.html` 的手动保存流程（`#cloudSave`，约 L5341-L5386）：

- 点击保存时先固定名称和待保存 JSON，再生成 2D 缩略图，保存按钮在操作期间禁用，避免重复提交。
- 先成功写入方案 JSON，再向 `PUT /api/plans/{name}/thumbnail` 上传 PNG；覆盖保存时新图替换旧图。
- 截图或缩略图上传失败不撤销已保存的方案，明确提示“方案已保存，但缩略图生成/上传失败”；JSON 保存失败仍沿用现有错误处理。
- `autoSave()` 保持原样，不在每 2 秒自动保存时重复栅格化；自动保存草稿和旧方案允许没有缩略图。

### 3. 后端管理独立 PNG 文件

修改 `app.py`：

- 基于 `plan_path(name)` 派生同名 `.png` 路径，继续使用现有方案名校验。
- `GET /api/plans` 仅增加可用缩略图 URL 和缓存版本，不读取或返回方案 state。
- 增加 `GET /api/plans/{name}/thumbnail` 返回 PNG；增加对应 `PUT`，校验请求大小、Content-Type 和 PNG 文件签名，并通过临时文件原子替换。
- JSON 覆盖保存后移除旧缩略图，避免新方案配旧图；删除方案时同时删除同名 PNG。
- 无需修改打包脚本：现有打包流程已经包含 `app.py` 和 `index.html`。

### 4. 打开方案卡片显示预览

修改 `index.html` 的方案卡片样式（约 L888-L958）和 `showWelcome()`（约 L5401-L5458）：

- 在卡片名称上方增加固定比例缩略图区域，图片使用 `object-fit: contain` 和统一米白背景，保持现有网格、当前方案高亮、删除和打开行为。
- 有 `thumbnail` 的方案加载对应 PNG；旧方案、自动保存草稿、内置示例及图片加载失败时显示“暂无预览”占位，不影响点击打开。
- 保存弹窗继续沿用现有紧凑列表，不额外改布局。

## 验证

1. 运行 Python 语法检查，并启动本地服务器，用浏览器打开方案界面。
2. 在 2D 视图保存新方案，确认生成同名 JSON/PNG，重新打开方案界面后卡片显示正确预览。
3. 在 3D 视图保存，确认全程不切换视图，缩略图仍为 2D 户型图。
4. 覆盖保存并修改布局，确认缩略图更新且不显示旧缓存；中文方案名的读取、上传、删除均正常。
5. 验证旧方案、自动保存草稿、示例方案及失败图片均显示占位；删除方案会联动删除 PNG。
6. 回归原“导出图片”、方案打开/加载、自动保存和空方案保存；确认列表接口不返回完整 state，方案 JSON 不包含图片字段。
